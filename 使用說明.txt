==================================================================
　上傳前假名化工具　使用說明
　政大研發處　v3.0
==================================================================

這個工具做什麼？
----------------
把 Excel 檔裡的「姓名／主持人／申請人」欄位，換成固定的代碼
（例如「王小明」→「T-3F9A21B8C4」），再交給外部 AI 分析。
姓名與代碼的對照表只留在你的電腦裡，不會跟著檔案出去。

同一個人在所有檔案、所有年度都是同一個代碼，
所以跨檔比對、跨年追蹤完全不受影響，分析結果不會有任何差別。


==================================================================
　第零步　先把資料夾放對位置（很重要，先做這個）
==================================================================

解壓縮之前，先在下載的 zip 檔上按右鍵 →「內容」→ 勾選最下方的
「解除封鎖」→「確定」，然後才解壓縮。
（Windows 11 開啟「智慧型應用程式控制」時，從網路下載、沒有數位
　簽章的 .bat 會被直接擋下，而且沒有「仍要執行」可以按。
　內容頁沒有「解除封鎖」這個選項，代表不需要，直接解壓縮即可。）

請把解壓縮出來的整個「假名化工具」資料夾，移動到本機硬碟，例如：

　　D:\假名化作業\假名化工具\
　　（若這台電腦沒有 D 槽，改用 C:\假名化作業\假名化工具\）

不要放在 Dropbox、OneDrive、Google 雲端硬碟這類會自動同步的
資料夾裡，也不要放在會被備份到雲端的「文件」或「桌面」。

也可以放在單位內部的共用磁碟，但要同時滿足兩個條件：

　1. 該位置不會再同步到任何雲端服務
　2. 資料夾權限只開給承辦人與職務代理人

共用磁碟的好處是換人承辦時 salt.txt 不會跟著某台電腦消失；
代價是看得到的人變多。若不確定共用磁碟有沒有連到雲端，
就放本機硬碟，另外把 salt.txt 備份到共用磁碟即可。

（工具不會對共用磁碟跳警告，只會對雲端同步資料夾跳。）

為什麼？
　　工具執行後會產生 _private\mapping.csv，裡面是真實姓名與
　　代碼的對照表。如果資料夾在雲端同步範圍內，這份對照表會被
　　自動上傳——姓名就離開了這台電腦，假名化的防護等於失效。

工具會幫忙檢查常見的雲端同步資料夾（紅色警示列），以及桌面、
文件、下載、暫存資料夾（橘色警示列）。若位置不對，開啟時會跳出
提醒。看到警示就先關掉工具、把資料夾移好，再從新位置重新開啟
（設定不會遺失）。

但這個檢查不是萬能：公司自己架的同步軟體、改過名字的雲端資料夾
它不一定認得。「沒跳提醒」不代表位置一定安全，請自己確認一次。

用示範檔練習階段可以先不管（那是虛構資料），
但換成真實名單之前一定要先移好。


==================================================================
　第一次使用（只做一次）
==================================================================

　　點兩下　1_第一次執行_安裝環境.bat
　　照畫面指示等它跑完（約 3-5 分鐘）。

　　中途若出現「要現在自動安裝 Python 嗎」，按 Y。
　　裝完 Python 後畫面會請你關掉視窗、再點一次這個檔案，照做即可。
　　最後會在桌面建立一個「假名化工具」捷徑，圖示是 CopyNoright 標章。

　　若桌面捷徑顯示的是空白或預設圖示：
　　　在捷徑上按右鍵 →「內容」→「變更圖示」→「瀏覽」，
　　　選工具資料夾裡的　假名化工具.ico　→ 確定。
　　　（有時要按 F5 重新整理桌面，或重開機一次才會更新。）


==================================================================
　每次使用
==================================================================

　　步驟 0　點兩下　2_啟動假名化工具.bat　（或桌面的捷徑）
　　　　　　在最上面的「步驟零　選擇專案」挑一個專案，
　　　　　　或按「新增專案…」開一個新的。

　　步驟 1　按「開啟 input 資料夾」，把要處理的 Excel 檔拖進去
　　　　　　（也可以按「選擇檔案加入…」，或直接拖到視窗上）

　　步驟 2　按「① 先檢視」確認它抓到的欄位是對的
　　　　　　（檢視不會建立或修改任何檔案，連 _private 也不會動）
　　　　　　再按「② 進行假名化」
　　　　　　跑完若跳出「處理未完全成功」，先看後面
　　　　　　「看到 ! 開頭的提醒怎麼辦」一節，確認後才上傳

　　步驟 3　按「③ 檢視」
　　　　　　會同時開啟兩個視窗：
　　　　　　　output　　＝ 假名化後的檔案，這些才可以上傳
　　　　　　　_private　＝ 鹽值與姓名對照表，只留在這台電腦
　　　　　　訊息區也會列出兩個資料夾的內容清單，方便核對。


==================================================================
　專案是什麼？（同時處理好幾件工作時看這裡）
==================================================================

一位同仁常常同時有好幾件工作要處理。每件工作放在自己的專案
資料夾裡，資料不會互相混到：

　　假名化工具\
　　└── 專案\
　　　　├── 國科會新進教師分析\
　　　　│　　├── input\　　　原始檔（不可上傳）
　　　　│　　├── output\　　 假名化後（可上傳）
　　　　│　　└── _private\　 salt.txt、mapping.csv、aliases.csv（不可外流）
　　　　└── 產學合作經費分析\
　　　　　　 ├── input\　…（同樣三個資料夾）

新增專案：按「新增專案…」，輸入名稱即可，資料夾會自動建好。
切換專案：從下拉選單挑一個，畫面下方的 input 清單會跟著換。


── 兩個要點 ─────────────────────────────────────

一、不同專案的代碼各自獨立。

　　每個專案有自己的 salt.txt，所以同一個人在 A 專案和 B 專案
　　會拿到不同代碼。這是刻意的設計，可以避免不同業務的資料
　　被人串接起來還原身分。

二、同一件業務要固定用同一個專案。← 這點最重要

　　需要跨年比較的業務（例如每年都要做的新進教師分析），
　　請年年都用同一個專案，把新年度的檔案放進去跑就好。

　　不要每年開一個新專案。新專案＝新的 salt.txt＝全新的代碼，
　　今年和去年就對不起來，跨年追蹤直接斷掉。

　　判斷方式很簡單：
　　　　專案 ＝ 一件「業務」，不是一個「年度」。


==================================================================
　三件絕對要記得的事
==================================================================

　1. 只有 output 裡的檔案可以上傳。input 裡的是原始檔，不可以上傳。

　2. 每個專案的 _private 裡都有 salt.txt 和 mapping.csv，
　　 絕對不可以外流。
　　 不要上傳、不要寄出、不要放雲端硬碟。

　3. 開始處理真實資料之後，永遠不要刪除 _private 資料夾。
　　 刪掉會讓明年的代碼跟今年對不起來，跨年分析就斷掉了。
　　 （視窗右下角紅字的「清除本專案代碼（僅示範階段使用）」按鈕，
　　 　只會清掉目前選到的專案。處理真實資料的專案永遠不要按。）


==================================================================
　先用示範檔練習一次
==================================================================

工具附了一個叫「示範專案」的專案，裡面有 4 份虛構的示範檔
（姓名用武俠小說角色，不是真人資料）。
選這個專案跑一次，確認畫面最後出現：

　　處理檔案　　：4
　　替換儲存格　：69
　　本次新增姓名：17（累計 17）

中間會出現一段橘色的「注意：偵測到 1 組疑似同一人的不同寫法」提醒，那是正常的，
示範檔故意放了同一個人的兩種寫法，讓你看到工具會幫你抓出來。
接著工具會問要不要做「姓名整併」，可以順便練習一次
（做法見後面的「姓名整併」一節）。

確認成功之後，不必清理示範專案，直接按「新增專案…」開一個
你真正要做的專案就好——專案之間互不影響，示範專案留著當
日後給新同仁看的教學範例即可。

（右下角紅字的「清除本專案代碼」只影響目前選到的專案。
　除非你不小心在真實專案裡跑了測試資料，否則永遠不需要按。）


==================================================================
　姓名整併：同一個人被打成兩種寫法
==================================================================

執行後若出現橘色的「偵測到 N 組疑似同一人的不同寫法」，
代表有人的姓名在不同檔案裡打法不一樣，例如：

　　「陳 小明」　和　「陳小明」　（多了空格）
　　「Wei Xiaobao」　和　「WeiXiaobao」
　　「陳小明 教授」「陳小明(召集人)」　和　「陳小明」　（多了稱謂或括號註記）

這種情況他會拿到兩個代碼，跨檔比對就對不起來。

工具會在執行完自動問你要不要處理；也可以隨時按步驟三的
「姓名整併…」按鈕開啟。


── 怎麼操作 ────────────────────────────────────

視窗上半部會列出每一組疑似同一人的寫法。
在每一組裡點選「要保留的正確寫法」，其餘寫法就會併到它身上。

　　中文姓名通常不含空格　→　多半保留沒有空格的那個
　　英文姓名通常要有空格　→　多半保留有空格的那個
　　多了稱謂或括號註記　　→　多半保留本名
　　不確定的，就選「先不處理」，去問來源單位確認後再回來處理

下半部的「手動整併」用在自動偵測抓不到的情況，最常見的是錯字：
例如「陳大文」被誤打成「陳大聞」。把兩個寫法照原樣輸入，
按「加入」即可。

最後按「儲存並立即重新執行」。


── 整併之後會怎樣 ──────────────────────────────

　・兩種寫法從此共用同一個代碼
　・被併掉的那個舊代碼會從 mapping.csv 移除（retired_codes.csv 寫不進去時
　　整批停下，不會移除），改記在
　　_private\retired_codes.csv——先前上傳過的檔案裡若有舊代碼，
　　用「查詢姓名」仍查得到是誰（會標示「這個代碼已整併」）
　・規則存在 _private\aliases.csv，之後每次執行都會自動套用，
　　包括明年的年度作業，不必重設
　・原始檔完全不動，工具只改 output 裡的結果

重要：整併會改變代碼。如果被併掉的那個代碼已經上傳出去了，
請用重新執行後的新 output 取代先前上傳的檔案，否則外部那邊
會同時存在新舊兩個代碼。


==================================================================
　換成真實資料之後：檔案中途更新怎麼辦
==================================================================

這是實際作業一定會遇到的狀況：檔案已經跑過了，結果同仁又補寄
一份更新版；或者三個單位的檔案不是同一天到齊。

核心觀念先講：
　　只要 salt.txt 不變，你隨時可以重跑、可以只放部分檔案、
　　可以分批處理，代碼都會一致。
所以中途更新完全不是問題。


── 為什麼可以放心 ──────────────────────────────────

代碼是「salt.txt ＋ 姓名」算出來的，跟「哪些檔案一起處理」
「處理過幾次」都無關。同一個王小明，今天跑、明天跑、單獨跑、
跟別的檔一起跑，只要鹽值沒換，永遠是同一個 T-XXXXXXXXXX。
（v2.4 以前建立的專案，既有人員沿用原本的 6 碼代碼，新加入的人
　才是 10 碼。這是為了讓跨年代碼接得上，不是錯誤。）

mapping.csv 也是累加的——每次執行只會新增沒見過的姓名，
不會清掉舊的。


── 三種更新情境的做法 ──────────────────────────────

情境一　某個檔案內容更新了（同一份檔案的新版）

　　直接用新版覆蓋 input 裡的舊檔，按「② 進行假名化」重跑。
　　・output 裡對應的檔案會更新成新版的假名化結果
　　・新版裡若有新面孔，mapping.csv 自動補上，舊代碼不受影響
　　・其他沒動到的檔案重跑也沒關係；只有這次多了新的姓名時，
　　　那些檔案的備註裡可能會多換掉幾處（多做，不會少做）

情境二　多來了一份新檔案

　　放進 input，重跑即可。已處理過的檔案會再處理一次，新檔案會被加進來。
　　新檔案帶來新的姓名時，舊檔案備註裡提到這些人的地方也會一併換掉，
　　所以舊檔案的結果可能比上次多換幾處（和情境一的最後一點同樣道理）。

　　若檔案很多、只想處理新的那一份，可以先把 input 清空，
　　只放新檔進去跑——同一個專案的 _private 沿用著，
　　代碼一定跟之前一致，output 裡的舊檔也不會被動到。

情境三　分批到齊，不想等全部

　　先到的先跑，後到的再跑第二次。每一批的 output 都可以
　　陸續上傳。這正是這個工具設計成「可重複執行、代碼一致」
　　的原因。

　　若兩批的檔名只差在副檔名（例如第一批是「查詢結果.xls」、
　　第二批是「查詢結果.xlsx」），工具不會覆蓋第一批的結果，
　　而是另存成「查詢結果(xlsx).xlsx」，並在畫面上提示。

　　（這個判斷靠 _private\output_sources.csv 記錄「哪個 output 來自哪個原始檔」。
　　　從舊版升級後的第一批、或這個檔被刪掉、損毀時沒有紀錄，工具不知道
　　　output 裡的同名檔是誰產生的，會先把它移到 _private\output_隔離\
　　　（不會刪除）再寫入新結果，畫面會提醒。）

　　檔名裡的人名被遮掉以後才撞名（例如「113_王大明_簽到」「113_李小華_簽到」
　　都變成「113_＊＊_簽到」），第二個檔會存成「113_＊＊_簽到_2.xlsx」。

　　但若第二批的檔名連副檔名都和第一批完全一樣，工具會當成
　　「同一份檔案的新版」，直接覆蓋第一批的 output。
　　兩批其實是不同內容的話，放進 input 之前請先改檔名
　　（例如「查詢結果_第二批.xlsx」）。


── 唯一的鐵則 ────────────────────────────────────

　　每個專案的 _private\salt.txt，從頭到尾都要是同一個。

只要它沒被刪、沒被換，上面所有情境都成立。

反過來說，唯一會出事的操作是：把 _private 資料夾刪掉再跑。
那會產生新的鹽值，所有代碼重新洗牌，新舊對不起來。

所以中途更新時，只動 input 和 output，絕對不要碰 _private。
（視窗右下角紅字的「清除本專案代碼（僅示範階段使用）」按鈕，
　在這個階段永遠不要按。）


── 實務建議對照表 ──────────────────────────────────

　想做的事　　　　　　　　　做法
　─────────────────────────────────────────
　檔案更新了　　　　　　　　覆蓋 input 舊檔 → 重跑
　多來一份　　　　　　　　　丟進 input → 重跑
　會不會影響舊代碼　　　　　不會，放心重跑
　想省時間只處理新檔　　　　清空 input，只放新檔進去跑
　重跑前想保險　　　　　　　先把該專案的 _private 複製一份備份
　開始一件新的工作　　　　　按「新增專案…」，不要跟舊工作混在一起
　明年再做同一件工作　　　　用同一個專案，不要開新的


最簡單的心法
　　不確定的時候，就把所有檔案（含更新後的）都放進 input
　　重跑一次。重跑是安全的、跑幾次結果都一樣，不會累積錯誤。
　　多花一兩分鐘，換一個「絕對不會弄錯」。


==================================================================
　salt.txt 與 mapping.csv 要長期保存
==================================================================

上面那條鐵則，延伸出去就是年度作業的關鍵：

明年的年度作業，只要選同一個專案，就會自動沿用今年的 salt.txt。
把新年度的檔案放進去跑，出來的代碼就和今年完全銜接。

所以每個專案的 salt.txt 都請務必長期保存：

　・在單位共用磁碟留一份備份
　・紙本抄寫一份存檔（它只是一串 32 位的英數字）
　・mapping.csv（姓名與代碼對照表）也要一起備份：外部分析結果
　　要還原成姓名時靠它；v2.4 以前建立的專案，舊的 6 碼代碼更是
　　只存在這份檔案裡，遺失就還原不回來
　・工具資料夾本身要放在本機（見最前面的「第零步」），
　　不要放在 OneDrive、Dropbox、Google 雲端硬碟等同步資料夾
　・備份到共用磁碟時，同樣確認該位置不會再同步上雲

承辦人交接時，salt.txt 與 mapping.csv 的交付與保管方式要一併寫進交接清單。
（這兩個檔都含可還原身分的資訊，備份位置同樣不可外流。）


==================================================================
　工具不處理的檔案
==================================================================

工具只處理 Excel 檔（.xlsx、.xls、.xlsm）。

.csv、.txt、.docx、.pdf 等其他格式「不會」被處理，也「不會」放進
output。訊息區會列出這些檔案，它們仍是原始資料，請勿上傳。
需要處理的話，先用 Excel 打開、另存成 .xlsx，再放進 input 重跑。

從舊版（v2.4 以前）升級的專案：舊版會把這類檔案原封不動複製進
output。新版執行時會先把 output 裡這類檔案移到
_private\output_隔離\（不會刪除），並跳出提醒。
如果你先前曾把 output 整包上傳，這些檔案可能已經外流，請通報主管。

照畫面提示處理後重新執行。常見的有：

　・檔案無法開啟、寫檔失敗（通常是檔案正被 Excel 開著）
　・mapping.csv 無法寫入（正被 Excel 開著）
　・output 裡已經有處理過的檔案，但 mapping.csv 不見了
　　→ 先用備份還原 _private\mapping.csv；output 的檔不要了就先移出 output
　・salt.txt 格式不對、有大寫英文字母，或和 mapping.csv 對不上
　　（抄錯一個字工具也會擋下）→ 用原始備份檔還原
　・mapping.csv、retired_codes.csv 被 Excel 另存成 ANSI，姓名有字變成「?」
　　→ 用 UTF-8 的備份還原（工具不會自動修正，因為缺的字已經找不回來）
　・retired_codes.csv 讀不到或寫不進去（整併時需要記下舊代碼）→ 關閉它或還原
　・aliases.csv（姓名整併表）讀不到 → 在「姓名整併」重新儲存，或用記事本另存 UTF-8

「·」開頭的是一般說明，例如哪些欄位被處理、文字裡「承辦人：○○○」
這類寫法的姓名換了幾處、哪些工作表沒有姓名欄也沒有像人名的內容
（例如統計表，原樣保留），不需要特別處理。


==================================================================
　欄位設定.txt：讓工具認得新的欄名
==================================================================

工具內建了一份欄名清單（姓名、主持人、申請人、電子郵件、電話…）。
遇到清單裡沒有的欄名（例如「校內分機」），不必改程式：

　1. 在工具資料夾（跟 anonymize.py 同一層）用記事本開一個新檔，
　　 檔名存成「欄位設定.txt」。
　　 也可以把「欄位設定_範例.txt」複製一份、改名成「欄位設定.txt」。
　2. 照下面的格式寫：

　　　# 井字號開頭的是註解，工具會略過
　　　[姓名欄]
　　　指導老師
　　　口試委員
　　　[清空欄]
　　　校內分機
　　　緊急聯絡人電話

　　 [姓名欄] 底下的欄位會換成代碼；[清空欄] 底下的欄位會整欄清空。
　　 一行寫一個欄名，要跟 Excel 裡的欄名一模一樣（空白與英文大小寫不拘）。
　3. 存檔後重新按「② 進行假名化」。
　　 訊息區最上面會出現「[欄位設定] 已套用 欄位設定.txt」。


── 英文或中英混排的名冊 ──────────────────────────

如果要處理的表格欄名是英文（Name、Principal Investigator、Employee ID…），
請改用「field_settings_example_EN.txt」，複製一份改名成「欄位設定.txt」即可。
裡面已經列好常見的英文欄名，說明也是英文的，可以直接轉給外籍同仁。

兩個注意事項：

　・區塊標記 [姓名欄]、[清空欄] 必須維持中文，欄名本身可以是任何語言。
　　寫成 [Name columns] 工具會回報「區塊名稱無法辨識」。
　・設定檔的檔名一定要是「欄位設定.txt」，這個中文檔名不能改。

欄名比對不分大小寫、忽略空白、忽略結尾冒號，所以
「Principal Investigator」和「PRINCIPAL  INVESTIGATOR：」都認得。
而且這份清單是「加進」內建的中文清單，不是取代它，
所以中英混排的表格不必另外設定。

但要知道它修不了什麼：句子中夾帶姓名的偵測，是為 2～3 字中文姓名設計的，
對英文姓名不適用。處理英文名冊時請以欄名清單為主，
並且一定要先按「① 先檢視」確認抓到的欄位正確。

這個檔案所有專案共用，一定要放在工具資料夾；放在專案資料夾或 input 裡
不會生效（畫面會提醒正確位置）。若訊息區出現「欄位設定.txt 有下列問題」，
代表有幾行寫錯沒有生效，照提示改好再重跑。


==================================================================
　工具做不到的事（上傳前一定要知道）
==================================================================

　・工具只認得「欄名」。欄名不在清單裡、也沒寫進欄位設定.txt 的
　　欄位，裡面就算都是姓名也不會被處理（欄名像人名或聯絡方式、
　　或內容多半像姓名時會提醒，但不保證每一種寫法都認得）。
　・備註、說明這類自由文字裡的姓名，工具只換得掉兩種：
　　1.「在姓名欄出現過的人」。姓名欄寫「王小明(召集人)」「王小明老師」
　　　「王 小明」時，別處的「王小明」也認得。
　　2. 幾種固定寫法：「承辦人：王小明」「聯絡人 王小明、李大華」「聯絡人（王小明）」
　　　（人員欄名後面接冒號、空白或括號）、「承辦人王小明負責彙整」（緊接
　　　姓名時，後面要是「負責、代理、處理、退休」這類字），以及格子開頭或
　　　標點、空白之後的「王小明老師／教授／先生／女士／小姐」（稱謂前可以
　　　空一格，英文全名也可以）。名字要是 3 個字（或複姓 4 個字）、而且是
　　　常見姓氏開頭；罕見姓氏認不出來。「感謝王小明老師」這種前面緊接
　　　中文字的不會換，只會提醒。
　　其他寫法裡從沒出現在姓名欄的名字，它不會換：「本表由王小明彙整」
　　「請王小明負責」這類寫法會提醒（三、四個字、常見姓氏開頭），
　　更自由的寫法（例如「王小明提供」）連提醒都沒有。
　・兩個字的姓名不會自動替換：出現在姓名欄的兩字姓名，在句子裡只提醒
　　（句首、句尾、標點旁邊，或前後是「由、與」「負責、代理」這類字才數得到，
　　其他夾在字中間的認不出來）；「承辦人：林森」「林森老師」這種固定寫法
　　接兩個字時也只提醒。
　・反過來，出現在姓名欄的三字姓名，別處「夾在詞裡」也會被換掉：姓名欄有
　　「江大海」時，「長江大海的研究」會變成「長T-…的研究」。姓名剛好是
　　常見詞的一部分時，請打開 output 看一下。
　・一格寫好幾個人（「王小明、李大華」）會整格換成一個代碼，和他們各自的
　　代碼不同（畫面會提醒）。
　・英文姓名在句子裡要跟姓名欄的寫法順序相同才換得掉（大小寫、
　　空白多寡不影響）。姓名欄寫「John Wang」、別的格子整格寫成
　　「Wang, John」可以認得；夾在句子裡的姓在前寫法認不得。
　・檔名、工作表名稱：已知的姓名會換成代碼（兩個字的姓名要整段相同，
　　例如「林森_名單」，不會動到「林森北路宿舍」）。不知道代碼的，只有
　　「確定像人名」的片段（常見姓氏開頭的 3 字姓名、複姓、○○○老師、
　　英文全名）才會改成「工作表N」或「＊＊」並提醒；兩個字、罕見姓氏、
　　原住民族名、外籍譯名認不出來，會原樣留著。
　・直式表單、合併得很複雜的表格，工具只能提醒，無法自動處理。
　・處理速度：因為新版多了「備註、說明等文字裡的姓名」掃描，大檔案會比 v2.4 慢一些。
　　實測（兩萬列三十欄、一萬二千列、100 個檔、60 個中型檔）都在 1.0～1.15 倍；
　　200 張工作表的檔案反而快很多（78 秒→10 秒）。
　　最慢的兩種情況是「姓名欄每一格都寫好幾個人」與「每一列都有很長的英文說明、
　　而且裡面提到名冊上的人」，約 1.6～1.8 倍（實測一萬列的檔案多 1 秒多）。
　・同一張工作表裡有第二段表格、但工具沒認出第二段的表頭時，第一段姓名欄
　　那一欄往下的內容（例如第二段的「月支酬金」和金額）也會被換成代碼。
　　代碼查得回原值；換到的是數字時畫面會提醒「姓名欄裡有編號或數字」。
　・原始檔改了檔名或副檔名（例如「名單.xlsx」改成「名單_修正.xlsx」）再重跑，
　　舊檔名的 output 不會自動移除（工具無法分辨它是舊版還是先前批次的另一份檔），
　　新舊兩份會並存。請自己把舊的那份移出 output。
　・output 只保留儲存格的「值」：顏色、框線、欄寬、合併儲存格都不會
　　保留；公式會變成 Excel 最後一次存檔時算出的數值；「#N/A」這類錯誤值
　　會變成空白；只有時間（沒有日期）的格子會變成文字；隱藏的工作表會
　　變成顯示。以「=」開頭的文字仍是文字，不會變成公式。需要原本格式的話，
　　請在原始檔上另外處理。

所以每次上傳前，請打開 output 裡的檔案快速看一遍：
姓名欄是不是都變成 T- 開頭的代碼、備註欄有沒有漏網的名字。


==================================================================
　不用了的時候：解除安裝
==================================================================

工具資料夾裡有一支「9_解除安裝.bat」，點兩下就會開啟解除安裝程式。

　　⚠　先讀這一段再動手
　　　　每個專案的 _private\mapping.csv 是「代碼與真實姓名」的
　　　　唯一一份對照表。刪掉之後，已經發出去的代碼永遠還原不回
　　　　姓名，明年的年度作業也會接不上（代碼會全部重新洗牌）。

程式一打開會先列出現況：有幾個專案、幾份對照表、合計幾筆姓名，
然後給你五個選項。預設什麼都不刪——直接按 Enter 一律是離開或取消。

　選項　做什麼
　─────────────────────────────────────────────
　1　　只備份資料，不移除任何東西（建議先做這個）
　2　　只移除桌面捷徑，程式和資料都不動
　3　　移除程式，保留資料。「專案」資料夾原封不動留著
　4　　完整移除，連資料一起刪
　5　　顯示 Python 與套件要怎麼移除（只顯示說明，不會動到電腦）
　0　　離開，什麼都不做

大多數人要的是選項 3：工具不想要了，但對照表要留著，
這樣明年若又要做同一件業務，把「專案」資料夾放回新版工具就接得回來。


── 關於備份 ────────────────────────────────────

備份的是「整個工具資料夾」，不是只挑幾個檔，所以你自己放在裡面的
檔案也會一起備份。複製完會逐檔比對 SHA-256，確認每一個檔案都和
原檔一模一樣才算成功；只要有一個對不上，就不會進行任何刪除。

備份資料夾裡會附一張「這份備份是什麼_請先讀我.txt」，寫明裡面有
什麼、以後要怎麼還原。

備份位置不可以選在工具資料夾裡面（刪除時會跟著消失），選到會自動
同步上雲的位置會跳出警告。

　⚠　備份裡有完整的真實姓名對照表。請比照公務個資保管：
　　　不要放進共用雲端硬碟；這台電腦若要交回或報廢，備份要先移走。


── 選項 4（完整移除）要通過四道關卡 ──────────────

　1. 確認要繼續
　2. 備份成功，而且逐檔 SHA-256 驗證通過
　3. 刪除前再驗一次（備份完成到你按下確認之間可能隔了一段時間）
　4. 手動輸入六個大寫英文字母 DELETE，再確認一次

任何一關沒過，一律什麼都不刪。


── Python 與套件不會被自動移除 ──────────────────

pandas、openpyxl、xlrd、tkinterdnd2 這些套件，以及 Python 本體，
這台電腦的其他程式很可能也在用，所以解除安裝程式不會去動它們，
只會在選項 5 顯示指令讓你自己決定。不確定的話就留著，不會有壞處。


── 找不到 Python 的時候 ────────────────────────

如果這台電腦的 Python 已經被移除，「9_解除安裝.bat」會改成顯示
手動移除的三個步驟（先備份「專案」資料夾、刪掉桌面捷徑、
再刪整個工具資料夾），照著做即可。
